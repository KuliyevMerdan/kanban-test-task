# Технические решения

Короткий журнал решений: что выбрали, почему и чем пожертвовали.

## 1. Монорепо на pnpm workspaces

`apps/api` (NestJS), `apps/web` (Next.js), `packages/shared` (общий контракт API).
Один `clone`, общие конфиги TypeScript/ESLint/Prettier, атомарные изменения «бэк + фронт» в одном PR.
Turborepo не используем: для двух приложений хватает `pnpm -r`, кеш сборки здесь не окупается.

## 2. Общий контракт в `@kanban/shared`

Enum'ы статусов и приоритетов, zod-схемы и DTO-типы описаны один раз и используются
и для валидации запросов в API, и для валидации форм на фронте. Расхождение контракта
ловится компилятором, а не в рантайме.

Пакет собирается `tsc` в CommonJS + `.d.ts`: так его без дополнительных настроек
потребляют и Nest (CommonJS), и Next.

## 3. Версии зависимостей

| Пакет      | Версия | Почему                                                                                                                                                        |
| ---------- | ------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| NestJS     | 11.x   | Nest 12 перешёл на ESM-only. Связка Jest + ESM + декораторы требует отдельной настройки, а 11.x по-прежнему получает патчи. Переход на 12 — отдельная задача. |
| TypeScript | 5.9    | Nest CLI 11 собирается на 5.9; `typescript-eslint` пока поддерживает только TS < 6.1, поэтому TS 7 сломал бы линтинг.                                         |
| TypeORM    | 1.x    | Актуальная ветка, поддерживается `@nestjs/typeorm` 11.                                                                                                        |
| Next.js    | 16     | App Router, актуальная версия.                                                                                                                                |
| MUI        | 9      | Актуальная версия, есть интеграция `@mui/material-nextjs/v16-appRouter`.                                                                                      |
| PostgreSQL | 17     | Стабильная версия, доступна на Render.                                                                                                                        |
| Node.js    | 24 LTS | Зафиксирована в `.nvmrc`.                                                                                                                                     |

## 4. Конфигурация через env с валидацией

API валидирует переменные окружения zod-схемой при старте и падает с понятной ошибкой,
а не на первом запросе к БД.
